# 编译与部署全流程指南

本文档覆盖「在线密码本」从**环境准备 → 编译 → 部署 → 运维 → 客户端使用**的完整过程，
面向首次接手项目的新同学或需要独立部署的运维人员。

---

## 一、系统组成与产物

| 组件 | 说明 | 编译产物 |
|---|---|---|
| 服务端 `cmd/server` | Go 单二进制，TLS 1.3 + SQLite（无外部依赖） | `编译/服务端产物/密码本服务端.exe` |
| 客户端 `client/app` | Wails 桌面客户端（管理员 + 普通用户，Windows） | `编译/客户端产物/在线密码本.exe` |
| 命令行客户端 `cmd/pbcli` | 无 UI 的命令行客户端（测试/脚本用） | `编译/客户端产物/密码本命令行.exe` |
| 工具 `cmd/keytool` | 密钥/证书工具 | `编译/客户端产物/钥匙工具.exe` |

**核心安全机制**：SM2 私钥口令加密存本地 → 注册凭证 attestation（`PB_REG_SECRET` 校验）
→ 一次性 bootstrap token（首次建立管理员）。

## 二、环境准备

### 1. 开发/编译机（Windows）

| 工具 | 版本 | 用途 |
|---|---|---|
| Go | ≥ 1.21 | 编译 Go 服务端/核心库 |
| Node.js + npm | ≥ 18 | 前端构建（Vite） |
| Wails CLI | v2 | 打包桌面客户端 |
| Git | 任意 | 版本管理 |

安装校验：

```bash
go version
node -v && npm -v
wails version
```

### 2. 部署机（Linux 服务器）

| 工具 | 用途 |
|---|---|
| Docker + docker compose | 容器化运行服务端（推荐） |
| OpenSSL | 生成 TLS 证书 |
| 安全组放行端口 | **8443/TCP**（HTTPS 服务端口） |

> 国内网络部署需先配置 Docker 镜像加速，见「五、服务端部署」第 0 步。

## 三、编译

编译脚本全部位于 `编译/` 目录，Windows 用 `.bat`（双击即可），Linux/macOS 用 `.sh`。

| 脚本 | 作用 |
|---|---|
| `编译客户端.bat / .sh` | 只编译客户端（GUI + pbcli + keytool） |
| `编译服务端.bat / .sh` | 只编译服务端 |
| `全部编译.bat / .sh` | 客户端 + 服务端一起编译 |

### 1. Windows 编译

```bash
# 全部编译（推荐，一步到位）
双击 编译/全部编译.bat
# 或命令行
编译\全部编译.bat
```

### 2. Linux 交叉编译（在开发机上为服务器编译）

```bash
# 编译 Linux 版服务端（.sh 内含 GOOS=linux GOARCH=amd64）
bash 编译/编译服务端.sh
```

### 3. 编译产物清单

编译完成后：

```
编译/
├── 客户端产物/
│   ├── 在线密码本.exe      ← 桌面客户端（发给用户）
│   ├── 密码本命令行.exe     ← pbcli（可选）
│   └── 钥匙工具.exe         ← keytool（可选）
└── 服务端产物/
    └── 密码本服务端.exe      ← 服务端（部署到服务器）
```

> 编译脚本内置 `-trimpath -ldflags "-s -w"` 优化（去路径 + 减小体积）。
> `.bat` 为 GBK 编码（Windows cmd 原生，避免中文路径乱码）。

## 四、部署前准备（证书 + 密钥）

### 1. 生成 TLS 证书（在部署机或本机）

```bash
# 第一个参数 = 输出目录；第二个参数 = 服务器对外 IP/域名（SAN）
bash scripts/gen-ca.sh ./deployments/certs 43.157.23.147
```

产出三个文件：

| 文件 | 用途 |
|---|---|
| `certs/ca.crt` | **CA 证书**——客户端「自签 CA 路径」必须填它（pinning） |
| `certs/server.crt` | 服务端 TLS 证书 |
| `certs/server.key` | 服务端 TLS 私钥（**勿外泄**） |

### 2. 准备部署密钥（.env）

服务端启动需要两个密钥，写在 `deployments/.env`：

```bash
PB_REG_SECRET=<随机长字符串>     # 管理员开户时校验成员公钥的凭证（长期有效）
PB_BOOTSTRAP_CODE=<随机hex>      # 首次建立管理员的一次性 token（用过即废）
```

生成随机值：

```bash
# REG_SECRET（URL-safe，32 字节）
python3 -c "import secrets; print(secrets.token_urlsafe(32))"
# bootstrap token（12 字节 hex）
python3 -c "import secrets; print(secrets.token_hex(12))"
```

## 五、服务端部署（Docker，推荐）

### 0. 国内网络配置（国内服务器必做）

```bash
sudo mkdir -p /etc/docker
printf '%s\n' '{"registry-mirrors":["https://docker.m.daocloud.io","https://registry.cn-hangzhou.aliyuncs.com"]}' \
  | sudo tee /etc/docker/daemon.json
sudo systemctl restart docker
```

### 1. 上传源码到服务器

```bash
# 本地：打包源码（git 跟踪文件）
git archive --format=tar.gz -o passbook-src.tar.gz HEAD

# 上传（scp/sftp 均可）
scp passbook-src.tar.gz ubuntu@43.157.23.147:/home/ubuntu/
```

### 2. 解压 + 生成证书 + 写 .env

```bash
ssh ubuntu@43.157.23.147
mkdir -p /home/ubuntu/passbook
tar -xzf passbook-src.tar.gz -C /home/ubuntu/passbook

cd /home/ubuntu/passbook
bash scripts/gen-ca.sh ./deployments/certs 43.157.23.147

cat > deployments/.env <<EOF
PB_REG_SECRET=<上面生成的>
PB_BOOTSTRAP_CODE=<上面生成的>
EOF
```

### 3. 构建并启动

```bash
cd /home/ubuntu/passbook/deployments
sudo docker compose build    # 首次构建较慢（拉 golang 镜像 + go mod 下载）
sudo docker compose up -d
```

### 4. 验证

```bash
curl -sk https://localhost:8443/healthz   # 期望输出: ok
```

服务端目录结构（部署后）：

```
/home/ubuntu/passbook/
├── deployments/
│   ├── certs/            # TLS 证书 + CA（勿动 server.key）
│   ├── .env              # 部署密钥（勿外泄）
│   ├── docker-compose.yml
│   └── data/             # SQLite 数据卷（服务端数据，备份对象）
└── scripts/
    └── gen-ca.sh
```

## 六、服务端运维

运维脚本 `编译/服务端运维.bat`（双击），底层是 `编译/server-ops.py`（SSH + paramiko）：

| 命令 | 作用 |
|---|---|
| `服务端运维.bat view` | 拉取当前 `PB_REG_SECRET` / `PB_BOOTSTRAP_CODE`（只读） |
| `服务端运维.bat reset` | **重置服务端**：清数据卷 + 生成新密钥 + 重启（**清空所有数据**） |
| `服务端运维.bat ca` | 下载服务端 CA 证书到 `编译/ca.crt`（证书变更后重新下载） |

> `reset` 场景：bootstrap token 已使用、需要重新部署管理员、或想清空测试数据。
> **注意**：reset 会删除全部用户/条目数据，生产环境慎用。

## 七、客户端使用

### 1. 启动前：准备 CA

客户端连接自签证书服务端必须指定 CA，用运维脚本下载：

```bash
编译\服务端运维.bat ca     # 生成 编译\ca.crt
```

### 2. 管理员（第一台机器）

```bash
编译\客户端产物\在线密码本.exe --admin
```

解锁页操作：
1. 服务端地址填 `https://<服务器IP>:8443`
2. 「自签 CA 证书路径」选 `编译\ca.crt` → 点「验证」（提示连接正常）
3. 自动进入「**管理员首次部署**」，填写：
   - 显示名（自定）
   - bootstrap token：`PB_BOOTSTRAP_CODE` 的值
   - REG_SECRET：`PB_REG_SECRET` 的值
   - 工号 + 口令（自定）
4. 点「部署并进入」→ 直接进入**管理面板**

> 之后每次启动 `--admin` → 填工号 + 口令 → 管理员登录 → 管理面板。
> 管理面板可：建组、加成员、开户、删成员、查看设备/主机信息。

### 3. 普通用户（其他机器）

```bash
编译\客户端产物\在线密码本.exe
```

解锁页操作：
1. 服务端地址 + CA（同上）
2. 「注册新账号」：填工号 + 口令 → 生成公私钥
3. 把显示的**公钥**复制给管理员 → 管理员在管理面板「成员开户」粘贴公钥
4. 回到客户端「注册设备」（工号自动沿用，填设备名可选）→ 进入密码本

> 管理员与普通用户**分库存储**：`--admin` 用 `admin.db`，普通模式用 `user.db`
> （都在 exe 同目录），同一台机器可同时测两个角色，互不干扰。

### 4. 数据目录

数据库文件与 exe 同目录（绿色便携，拷走即用）：

```
在线密码本.exe 所在目录/
├── admin.db       # 管理员数据（--admin 模式）
└── user.db        # 普通用户数据（普通模式）
```

## 八、常见问题

| 问题 | 处理 |
|---|---|
| **验证失败 unknown authority** | 解锁页 CA 路径没填/填错 → 重新 `服务端运维.bat ca` 后重填 |
| **bootstrap token 已使用** | token 一次性，部署成功即废 → 执行 `服务端运维.bat reset` 换新 |
| **普通用户显示离线** | ① 确认 CA 正确、地址可达；② 同步方式是否设为「手动」（设置页可改回自动） |
| **新建条目提示缺少组 ID** | 成员入组后需**登录一次触发同步**（同步状态组列表才刷新）；管理员端也登录一次补发组密钥 |
| **CA 证书变更后连不上** | 重新 `服务端运维.bat ca`，客户端解锁页重新选 CA |
| **同一台机器测两个角色** | `--admin` 走 admin.db、普通走 user.db，分库互不影响 |
| **服务器在国内拉不动镜像** | 按「五-0」配置 Docker 镜像加速 |

## 九、一句话流程速查

```
编译：全部编译.bat → 产物在 编译/客户端产物 + 编译/服务端产物
证书：scripts/gen-ca.sh → deployments/certs/ca.crt
密钥：生成 PB_REG_SECRET + PB_BOOTSTRAP_CODE → 写 deployments/.env
部署：上传源码 → gen-ca.sh → docker compose build && up -d → curl healthz
运维：服务端运维.bat [view|reset|ca]
客户端：管理员 --admin / 普通用户，填地址+CA，按引导部署/注册
```
