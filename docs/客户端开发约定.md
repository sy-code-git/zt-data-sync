# 客户端开发约定（在线密码本）

- **版本**：v3.0（2026-08-11 随主设计文档五修订同步发布；条目数据模型已与主文档 §5.1 统一为树形结构）
- **配套文档**：《设计文档-v3-无感协同版》（下称"主文档"）
- **范围**：约定客户端**除「加解密」与「同步引擎」之外的全部逻辑**——UI 壳、数据组织（树）、本地编辑、变更应用、冲突解决交互、辅助功能。
  - 加解密：主文档 §4（`internal/crypto`）
  - 同步引擎：主文档 §7（`client/core/syncer`）
  - 库边界：主文档 §3.1（`client/core` / `client/app`；管理面板为 `client/app` 的 `--admin` 模式；server 禁止 import client/core）

---

## 1. 数据组织（树形模型）

- 一条目 = 一个树节点，六类 `type`：`project / env / ip_type / acc_type / account / custom`，`parent_id` 指向父节点；数据模型见主文档 §5.1。
- 客户端负责：
  - **树组装**：按 `parent_id` 组装「项目 → 环境 → IP 类型 → 账号类型 → 账号」固定五层骨架；`custom` 万能节点是旁挂在各层下的**叶子补充卡片**（承载结构信息，不挂子节点、不组织账号）；
  - **同层排序**：树内同一层级（同一 parent_id 下）的节点**按 `title` 升序排序**（title 相同再按 `entry_id` 兜底），由客户端 core 的 `ListEntries` 统一返回排序后的列表，树组装保留该顺序；
  - **筛选索引**：解锁后内存建立 project / env / ip_type / acc_type / ip / account 字段索引，支持任意组合筛选；`custom` 节点的 title 与 custom_fields 键值纳入内存检索（散乱结构信息可搜）。
- 单条密文包上限 256KB（单节点体积极小，不会触碰）。
- 对齐键 = `entry_id`（UUID）：层级重命名不丢关联；复制条目时整体重新生成 id。

## 2. 本地编辑逻辑（本端操作）

- **本端新增 / 编辑 / 删除：立即生效**——直接写本地并标 dirty，推送交给 syncer；**本端操作绝不进入任何确认流程**。
- 编辑条目时保存**编辑前快照**（`local_entries.base_enc`），供冲突三路合并（主文档 §7.3）。
- 删除走墓碑语义（push `deleted=true`）；还原 = 生成新 `entry_id` 重新发布。
- 删除项目 = 批量推送该项目子树全部节点的墓碑。

## 3. 变更应用策略（远端变更）★ 核心约定

**边界（不可破坏）**：
- 服务端 → 客户端只**主动推送（SSE）或被动拉取**「新增 / 更新 / 删除」三类变更消息（带 seq 的密文或墓碑）；
- **服务端不直接修改客户端本地数据**——把消息应用到本地（写库）是客户端逻辑。

**一期实现：自动应用**（推荐默认行为）——

| 远端消息 | 本地行为（自动应用） |
|---|---|
| 新增 | 解密后自动入库 |
| 更新 | 本地无修改 → 自动覆盖入库；本地有未推送修改 → 三路合并（§7.3） |
| 删除（墓碑） | 自动本地删除（进 30 天回收站） |

**约定标注：建议自动应用**——若后续产品需要"用户确认制"（更新/删除由用户决定是否应用），仅在应用层加**确认队列**即可，不影响 core 与同步协议；确认机制**只针对远端变更**，本端操作永远直接生效。三期可提供"自动应用 / 用户确认"切换开关。

## 4. UI 壳约定（client/app）

- 只调用 `client/core` 公开 API；**不实现任何业务逻辑**；绑定方法签名不得出现密钥类型；输入输出均为可序列化结构。
- 前端禁止 `localStorage` 存敏感数据；页面数据全部来自 Go 层内存视图；密钥不跨层（前端永不触碰私钥/DEK/KEK）。
- 页面：解锁页（自动锁定倒计时提示）、树形浏览（项目→环境→IP类型→账号类型→账号 五层骨架 + 各层旁挂 custom 补充卡片；**已归档组整体只读标记、禁止编辑入口**）、条目编辑（树形递归表单：account 用固定模板，custom 用**通用动态表单**按 custom_fields 自动生成输入项，含密码生成器一键填入）、冲突解决页（三栏 diff，条目级）、设置页（锁定策略、自动解锁开关、同步状态）。
- 冲突解决交互：仅冲突条目进入三栏 diff，逐字段「采用本地 / 采用服务端 / 手动编辑」；自动合并成功的字段直接显示结果（主文档 §9.2）。

## 5. 辅助功能

| 功能 | 约定 |
|---|---|
| 密码生成器 | `crypto/rand`，可配长度（默认 16）/字符集/排除易混字符；仅本地出现，不出网不落盘明文 |
| 自动锁定 | 失焦连续 5 分钟 → 锁屏并 Wipe 内存密钥；解锁策略三选一（口令 / Windows Hello（三期）/ DPAPI 自动解锁） |
| DPAPI 自动解锁 | KEK 写 Windows DPAPI（TPM 保护）；keyfile 导入/导出、口令修改强制手输口令；口令修改成功后须用新 KEK 重写 DPAPI 凭据（主文档 §4.4） |
| 心跳 | `POST /auth/heartbeat`：启动/解锁立即一次 + 每 30s 一次，上报 `hostname`（机器名）；注册时只记注册名 + 注册 IP |
| 剪贴板 | 复制密码 30s 后自动清空 |

## 6. 二期边界

- UI 完善只许动 `client/app/frontend` 与绑定层；`client/core/api` 契约保持不变（主文档 §14.2）。
- 第三方 UI 基于 `client/core` 自行开发时，同样遵守本约定第 3/4 条（变更应用是客户端逻辑、UI 壳无业务逻辑）。

## 服务端地址配置与持久化（§9.2 新增，2026-08-12）

- 服务端地址+端口写入客户端本地配置；带本地数据库时写入库中（`app_config` 单行表，不落前端 localStorage）。
- 首次使用走完整初始化配置引导：必填「服务端地址」→ 验证通过（心跳/同步探活确认地址可达且鉴权有效）→ 进入主界面。
- 后续启动从本地库自动带出上次地址，不必重设。
- 设置页可修改服务端地址+端口；修改后重新验证并重连（token 不变）。
- 支持附加参数（`--reinit`）重启初始化配置引导：忽略已存配置重新走首次引导。
