# Git 通用约定

> 本约定适用于本仓库：**开发在 dev、测试通过后 squash 压成一个提交进 main、推远端、回同步 dev；dev 历史只在本地，远端永远干净。**

## 一、分支模型

| 分支 | 定位 | 远端 | 说明 |
|------|------|------|------|
| `main` | 发布分支 | ✅ 推送 | 只保留干净发布历史 |
| `dev` | 开发分支 | ❌ 不推送 | 保留完整开发历史，仅本地 |

**原则**：远端永远只有 `main` 一个分支，开发痕迹不外泄。

## 二、提交规范

- 提交信息使用**中文**，简洁说明意图
- 按**主题拆分**提交，同主题改动合并为一个原子提交
- 提交信息**不含项目代号、内部命名、敏感信息**（如公司名、项目代号、账号）
- 仅用户明确要求时才提交

## 三、合并策略（squash）

**门禁**：合入前必须完整测试通过（单测 + 前端测试 + vet）。

```bash
git checkout main
git merge --squash dev            # 首次加 --allow-unrelated-histories
git commit -m "发布: <说明>"
```

**效果**：dev 的整段开发历史压成 main 上一个干净提交，dev 提交对象不进远端。

**同步**：合入后立即回同步，保证下次 squash 从新基点计算 diff：

```bash
git checkout dev && git merge main
```

## 四、推送规则

- 仅推送 `main`（如 `git push github main && git push gitee main`）
- **合入 + 推送 = 连带操作**，必须经用户明确确认
- 任何 `git push` 前先征得同意，禁止擅自推送
- dev 不配置 upstream，裸 `git push` 不会误推

## 五、安全约定

- 敏感信息（密钥 / 密码 / 真实 IP / 账号）不入库、不提交、不进历史
- 默认密钥留空，密钥通过编译期注入或运行时 `-k`/环境变量提供
- 历史需清理时，本地 dev 保留完整历史，远端只留干净基线

## 六、完整工作流

```
开发(dev) ──测试通过──▶ 确认 ──▶ squash 合入 main ──▶ 推送远端 ──▶ 回同步 dev
```

---

**一句话概括**：开发在 dev、测试通过后 squash 压成一个提交进 main、推远端、回同步 dev；dev 历史只在本地，远端永远干净。
